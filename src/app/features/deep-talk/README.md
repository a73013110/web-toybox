# Deep Talk

抽一疊由淺入深的問題，陪兩個人聊得再深一點。

題庫存在 Google Sheet，改題目不用動程式碼、也不用重新部署。熱門排行來自真實使用者按的「很讚」，不是模型猜的。

---

## 使用者會經歷什麼

1. **挑條件**（三步）：關係階段 → 深度上限 → 主題想聊／不要
2. **洗牌**：動畫底下正在跟後端要一疊牌
3. **抽卡**：一次一題，一疊 8 張，每題可以按「很讚」或「跳過」，也可以複製文字或存成卡片圖
4. **收尾**：整疊的回饋一次送出，然後可以再來一疊

另外有一個獨立的熱門排行畫面。

---

## 兩個核心設計

### 深度是天花板，不是每張的深度

使用者選「坦白」不代表八張都是坦白題 —— 第一張就問最私密的問題沒有人接得住。牌組會自己爬坡：

| 深度上限 | 一疊 8 張的組成                       |
| -------- | ------------------------------------- |
| 破冰     | 破冰 ×8                               |
| 認識     | 破冰 ×3 → 認識 ×5                     |
| 深入     | 破冰 ×2 → 認識 ×3 → 深入 ×3           |
| 坦白     | 破冰 ×1 → 認識 ×2 → 深入 ×3 → 坦白 ×2 |

第二疊之後（`warm`）暖場已經做完了，直接往深處去：深入變成「認識 ×2 → 深入 ×6」，坦白變成「深入 ×3 → 坦白 ×5」。

某一層題目不夠時會從計畫涵蓋的其他層補滿，但**絕不會超過使用者設定的上限**，補完還會重新排回由淺到深。

### 只在選完條件時連線一次

整疊牌一次拿回來，之後翻牌都在前端跑。每翻一張就連一次會慢，也很快會吃掉全站的節流額度。回饋同樣是整疊累積、最後一次送出；中途離開時用 `sendBeacon` 補送。

補送有三個觸發點，缺一不可：`pagehide`（行動瀏覽器關頁）、`visibilitychange`（桌機切分頁），以及 Store 銷毀時的 `DestroyRef.onDestroy`。最後一個是 SPA 才有的情況——點「作品目錄」回首頁不會關掉頁面，前兩者都不會觸發，少了它票就直接消失。

## 怎麼寫一題好題目

第一版題庫寫壞了，原因是題目長這樣：「你怎麼看待錢跟自由的關係？」看起來很深，但當場答不出來 —— 它要求對方先歸納自己的一生再給結論。

聊得起來的問題都指向一個**具體的座標**：一次記憶、一個數字、一個二選一、一個假設情境。每一題都應該落在下面六種句型之一：

| 句型         | 不要                     | 要                                                               |
| ------------ | ------------------------ | ---------------------------------------------------------------- |
| 情境假設     | 你重視誠實嗎？           | 如果我做了一件你不能接受的事，但事前就誠實告訴你，你會怎麼看我？ |
| 二選一       | 你會怎麼定義安全感？     | 被秒回訊息跟被記得小事，哪一個比較有安全感？                     |
| 具體記憶     | 你什麼時候會覺得孤單？   | 你上一次打了字又刪掉，是想跟誰說什麼？                           |
| 尺度         | 你怎麼看待金錢與自由？   | 存款到多少，你才會覺得自己是安全的？                             |
| 釘住抽象詞   | 你覺得自己是什麼樣的人？ | 你說一個人「很好相處」的時候，具體是指他做了什麼？               |
| 第三人稱代入 | 你怎麼看待劈腿？         | 如果好朋友的另一半在外面亂搞，你會告訴他嗎？                     |

另外兩條：

- **「我」只能出現在曖昧中以後的題目裡。** 剛認識就問「你最怕我知道你的哪一面」太快了。
- **40 個字以內。** 卡片圖最多排八行，超過會自動縮字級，太長就不好看了。

這些規則同時寫在 [`app-deep-talk-ai.gs`](../../../../apps-script/app-deep-talk-ai.gs) 的 `deepTalkStyleRules()` 裡，是 Gemini 生題目時的主要約束 —— 少了它，模型預設就會寫出左欄那種題目。

## 聊不下去了？

一副問題卡真正的失敗不是抽到爛題目，是**對方答完了，然後兩個人都不知道要接什麼**。卡片上第三顆按鈕就是為了那一刻。

點下去展開兩段內容：

1. **別人問過的**（最多三則）。讀試算表就有，零延遲、零成本，所以這是預設路徑。
2. 底下一個輸入框。想往哪個方向追問可以打幾個字，**留空也可以** —— 會按這顆按鈕的人多半就是想不到方向。按下去才會叫 Gemini 生三個追問。

生出來的追問會累積下來，下一個抽到同一題的人先看得到。所以這顆按鈕按得越多，第一段就越有內容，而第一段是不花錢的。

**你輸入的方向不會給別人看。** 只有 AI 生的追問會被展示。原因與其他防守見 [`apps-script/README.md`](../../../../apps-script/README.md#追問)。

追問失敗（配額用完、網路不通）不會擋住任何事，卡片照抽，只是那一區顯示一行「AI 這次沒想出來」。

## 改題庫

直接改 Google Sheet 的 `questions` 工作表就好，**不需要動這裡的任何檔案**。

只有一種情況要改程式碼：**新增或改名主題／深度／關係階段**。那時要同時改兩個地方，字串必須完全一致：

- `taxonomy.ts`（前端的選項）
- 試算表的下拉選單（題庫的值）

深度還多一個地方：`apps-script/app-deep-talk.gs` 的 `deepTalkDepths()` 與 `deepTalkDeckPlan()`，以及 `app-deep-talk-ai.gs` 的 `deepTalkDepthBrief()`。

題庫的欄位定義與設定步驟見 [`apps-script/README.md`](../../../../apps-script/README.md#deep-talk-題庫)。

---

## 顏色

這一頁把共用層的 `--accent`、`--accent-soft`、`--accent-faint` 換成磚紅色系。`--paper`、字體、間距、圓角都沿用，所以看起來仍然是同一個站。

`#a83f22` 是挑過對比度的：在 `--paper` 上約 5.7:1、在 `--paper-deep` 上約 5.2:1，都過 WCAG AA。更亮的 `#c1543a` 只有 4.2:1，因此只留給不承載文字的光暈。

## 已知限制

- **無痕模式下記不住進度。** 看過的題目與上次選的條件存在 `localStorage`，存不了就每次都從頭開始，不影響功能。
- **票數擋得住隨手灌，擋不住有心人。** 前端不讓同一疊重複投，後端限制一次請求對同一題最多各加一票，再加上全站節流。票數只用來排序與淘汰題目，不是需要嚴格防偽的資料。
- **改完試算表最多五分鐘後才生效。** 題庫在後端有快取。想立刻生效見 `apps-script/README.md` 的 flush 動作。
- **存圖在 iOS Safari 多半是直接開啟圖片**，而不是存到相簿，使用者長按仍然可以存下來。
